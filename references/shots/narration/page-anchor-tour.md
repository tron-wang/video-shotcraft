name: page-anchor-tour
一句话: 虚拟相机按口播顺序走访长页上的一串兴趣点，讲到哪一处就已经把那一处取好景（小框推近、大框拉远），再一次滑到下一站
适用: 证据段——一段口播要点名原文里 2–4 个分散的位置（标题 → 一张图 → 一句关键句）；位置相隔很远、或口播顺序和原文顺序不一致；来源是新闻 / 公告 / 报告长页
时长: 6–12s（demo 8s / 240f，三站）；每站停 1.3–2s，站间滑行 0.8s
能量: 中低（停的时候几乎静止，滑行是全镜唯一的动作）
input: [screenshot]
narration: evidence

## 意图
口播说"标题写的是……、这张图显示……、文中还提到……"时，观众需要的不是陪着读完全文，而是"他说的那个东西就在这里"。所以这一镜不滚动、不巡航：相机只在兴趣点之间移动，每一站在词锚那一帧**已经停好**，框四周留出舒服的边，观众的眼睛不用找。位置和缩放一起变，读起来像有人拿着相机在一张大海报前走位。要逐行强调交给 `marker-sweep`；要"一起读"用 `page-scroll-read`。

## 动效核心
- 相机是帧号的纯函数 `cameraAt(frame, props) → { cx, cy, scale }`：面板中心对着的页面点 + 缩放。`planTour(props)` 先把每一站的取景与滑行时段排好，可单测
- 取景：`scale = min(面板宽·(1−2·margin)/框宽, 面板高·(1−2·margin)/框高)`，再钳进 `[minScale, maxScale]`；相机中心 = 框中心，然后钳进页面——**面板四缘永远不露出页面以外**（所以贴着页边的框会偏向一侧，这是对的）
- 滑行：`cx / cy / ln(scale)` 共用同一条 `inOutCubic` 进度，结束帧正好是 `at`。缩放在对数域插值，推拉的"倍率速度"才匀；三个量同起同落，读作**一次**运镜而不是先平移再缩放
- 长跳（屏幕位移 > 1.5 个面板高）：缩放再乘 `1 − dip·4p(1−p)`，中段轻轻拉远、赶路、再推近，`dip` 随距离从 0 加到 12%（3 个面板高时加满），同时滑行时长放宽到最多 1.5 倍。`dip` 会先被收小到不跌破缩放下限，不做事后硬钳（硬钳会在缩放曲线上留折角）
- 停靠时极缓推近：缩放从到站走到真正离站，线性 +1.5%，画面不死；取景上限预留了这 1.5%，推完正好到 `maxScale`。下一段滑行从推完的缩放接着走，缩放曲线连续
- 开镜：停在"用第一站的缩放看页顶"（或 `startBox`）。第一站本来就在页顶（标题）时，起始取景与第一站相同，相机开镜就架在站上、只做极缓推近，角标仍等到 `at` 才出现
- 角标：停好后四角长出强调色细角（5px 粗、46px 长，从外侧 10px 收拢到位，12f），离站前 8f 淡出；未到站完全不存在。位置逐帧按相机换算，推近时贴着框走
- 页面装在安全区大小的圆角面板里（圆角 28）；上下 96px 渐隐到纸色，但**只在那一侧还有页面时才出现**——相机贴着页顶时不会把报头融掉。整个面板 `slowPush` 1/1.04 → 1.00

## 参数表
| 参数 | 典型值 | 调节手感 |
|------|--------|----------|
| `stops[].x / y / w / h` | `boxes.json` 的框（页面 CSS px） | 给"要观众看的东西"的外包框：一句话给整句、图给整张图。框太细长（单行长句）时取景由宽度决定，上下会很空，可以把框高手动加到 2–3 行 |
| `stops[].at` | `f(tWord(i, '词'))`，取口播点到这一处的**那个词** | 这是"已经取好景"的帧；滑行在它之前 `travel` 帧开始 |
| `stops[].hold` | 40–60f（demo 48 / 52 / 44） | ≈ 口播讲这一处的时长；< 24f 眼睛还没落稳就走，> 90f 只剩 1.5% 推近撑不住 |
| `travel` | 24f | 一次滑行。18 以下像甩镜，36 以上像拖。长跳自动 ×1–1.5 |
| `margin` | 0.16（每边占面板的比例） | 0.1 框顶到面板边、显得挤；0.25 以上框变小、上下文变多，像"指给你看在哪"而不是"给你看" |
| `minScale` / `maxScale` | 0.6 / 1.8 | 下限实际取 `max(minScale, 面板宽/页宽, 面板高/页高)`——1080 宽的页实际下限是 0.889；上限硬钳 2（见已知坑） |
| `startBox` | 不给 | 想让开镜落在头图 / 报头而不是页顶时给 |
| `brackets` | `true` | 整页已经很满、或后面紧接 `marker-sweep` 时关掉，别两层强调 |
| `CREEP` | 0.015 | 停靠推近量。再大会在 60f 的停留里读成"又在推"，和滑行抢戏 |
| `MAX_DIP` / `LONG_JUMP` | 0.12 / 1.5 面板高 | 长跳的拉远量与起算距离 |
| 视窗 | SAFE 全区 960×1270，圆角 28 | 渐隐色 `fadeColor` 取页面底色，深色页面记得换 |

## 声音
停靠时不配音。滑行给一声很轻的位移：`transition/sweep-short.mp3` 音量 0.18，对齐滑行起点（`at − travel`），尾巴落在 `at`；长跳可换 `transition/swoosh-slow.mp3` 0.2。纸媒皮换 `paper/paper-slide.mp3` 0.2。只有当滑行落在句间气口时才配——`at` 紧贴上一句尾字的那一次宁可不配；一镜最多配两次，音量一律 ≤ 0.35。

## 已知坑
- **小框撞上限，字会糊或不够大**：`page.png` 是 2× 截图，缩放 > 2 就是在放大像素，所以 `maxScale` 无论传多少都硬钳在 2，取景再预留 1.5% 给推近（预设 1.8 → 实际到站 1.773）。一个 200×30 的小数字按 `margin` 算想要 3.3 倍，只会拿到 1.77 倍，框在面板里只占三成宽。`planTour(props).parks[i].capped === 'max'` 就是这种情况：要么把框扩成"数字 + 它所在的那一行"，要么这个点改用 `loupe-peek` / `stat-punch` 另起一镜，不要调高 `maxScale`
- **大框撞下限**：整页宽的图（912 宽）想要 0.72 倍，但 1080 宽的页在 960 面板里最小只能到 0.889（再小就露出页面以外），`capped === 'min'`，左右留白会比 `margin` 少。可接受；若框比面板还高（长表格），这张卡装不下，改用 `page-scroll-read` 滚过去
- **长跳很快**：demo 以外实测 2400 页面 px 的回跳在 36f 里完成，峰值约 280 屏幕 px/帧，中段文字必然看不清——这是设计（赶路不是给人读的），拉远 12% 只是让人看出"在往上 / 往下走"。一镜里长跳超过一次就显得焦躁，拆镜
- **站间太挤**：上一站 `at + hold` 到下一站 `at` 不足 `travel` 时，滑行先压短到可用时长（最短 10f），再不够就吃上一站的停留（最少留 12f，记在 `parks[i].heldShort`），仍不够就迟到（`late > 0`）。分镜阶段跑一次 `planTour`，`late` / `heldShort` 非零就删一站
- **什么时候该选 `page-scroll-read`**：兴趣点在同一屏或相邻两屏、顺序与原文一致、口播是在"读原文"（连续引两三句）——那是阅读，用滚动；相机来回推拉只会打断阅读。反过来，点与点相隔 > 1.5 屏、要回头、或点的大小差很多（标题 vs 一句话 vs 一张图）就用这张
- **贴页边的框不会居中**：正文左对齐、框靠左时，相机被页面左缘钳住，框会落在面板偏左。不要为了居中去放宽钳位——露出页面以外的底色比不居中难看得多
- `at` 是"取好景"的帧。把 `tWord` 当成滑行起点会整整晚一个 `travel`
- 页面层用 2D 的 `translate(...) scale(...)`，**不要写 `translate3d`**（同 `page-scroll-read`：独立合成层在小数缩放下会从圆角裁切边漏 1px 亮线）。`boxes.json` 是 CSS px，`<Img>` 宽设成 `pageW`，缩放只交给相机，不要两头各缩一次
- 缩放逐帧变化时小字会有轻微的次像素闪动，1.5% 的推近下肉眼不可见；若换皮后用了很细的衬线体发现闪，把 `CREEP` 降到 0.01

## 参考实现
demos/narration/page-anchor-tour/PageAnchorTour.tsx（`PageAnchorTourShot` 为镜头本体，`cameraAt` / `planTour` 为可单测的纯函数）

成片接法：
```tsx
import boxes from '../../public/pages/<slug>/boxes.json';
const b = (key: string) => boxes.boxes.find((x) => x.key === key)!;
const at = (i: number, w: string) => f(tWord(i, w)) - shot.from;
<PageAnchorTourShot
  duration={shot.duration}
  page={<Img src={staticFile('pages/<slug>/page.png')} style={{ width: boxes.page.width }} />}
  pageW={boxes.page.width} pageH={boxes.page.height}
  fadeColor={theme.paper}
  stops={[
    { ...b('headline'), at: at(2, '標題'), hold: 48 },
    { ...b('text-1'), at: at(3, '成長'), hold: f(tLine(3).end) - f(tWord(3, '成長')) },
    { ...b('chart'), at: at(4, '圖表'), hold: 44 },
  ]}
/>
```
`at` 取口播点到该处的那个词的 `tWord`（减去本镜 `from` 换成镜内帧号），`hold` 取讲完这一处的帧差；素材来自 `capture-page.mjs` 产出的 `assets/pages/<slug>/{page.png, boxes.json}`，`--text` 给的第 n 句对应 key `text-n`。写完先跑 `planTour(props).parks`：`late` / `heldShort` 全为 0、`capped` 没有意外的 `'max'` 才算过。画面下方按版面表放来源条（`source-strip`）。

name: screen-photo-fisheye-focus
一句话: 把真实页面截图拍成"手机对着显示器拍"——以画面中心为光轴的桶形畸变 + 源空间扫描线与屏幕扫描线干涉出的摩尔纹 + 径向暗角；取景点从页面中心推近到目标短语（zoom 1.3→2.35），落定后黄色荧光笔在源图坐标里自左向右涂过、跟着畸变一起弯，末段继续微推
适用: 用户证言/真实反馈/通知/榜单截图的"证据镜头"；需要"这是真的、有人拍下来发给我"的 UGC 质感；在一串干净 UI 镜头之间做一次质感反差
时长: 约 5s（150f@30fps；推近 f12–66、荧光笔 f70–88、落定后 62f hold）
能量: 中低（全程只有一次推近和一次涂抹，质感本身就是信息）
标签: camera

## 意图
干净的 UI 截图读作"官方宣传"，观众默认打折。屏摄质感把同一张截图变成"有人拿手机
拍下来的证据"——桶形畸变、摩尔纹、暗角是所有人都见过的"拍屏幕"视觉签名，不用任何
说明文字就能触发"这是真实场景"的联想。荧光笔再把视线钉到那一句话上。

关键取舍是荧光笔画在**源图坐标**里而不是屏幕坐标：它跟着畸变弯，也被摩尔纹覆盖，
读作"屏幕上被划了重点"。叠在最上层的平直黄色矩形会立刻暴露成后期贴纸。

## 动效核心
- **逐像素反向映射**：输出像素 p（以画面中心为原点、x 乘宽高比）→
  `k = (1 + strength·r²) / zoom` → 源坐标 `focus + p·k` → 双线性采样。采样越出截图时按
  越界距离 ×12 压黑，形成弧形黑边——这就是"显示器边框"
- **光轴钉在画面中心**，推近时平移的是**取景点** focus（源图坐标），畸变中心不跟着跑。
  畸变中心跟着聚焦点移动会读作"一块放大镜在屏幕上滑"；钉中心才是"手机镜头在推"
- **摩尔纹 = 两组扫描线的拍频**：源空间线 `sin(sv·900)`（随畸变弯）× 屏幕空间线
  `sin(vy·900·1.045 + 1.3)`（固定在画面上），`moire = mix(fine, beat, 0.65)`，
  `color *= 1 − 0.2·moire`。zoom 一变，拍频条纹会自己爬动——真实屏摄就是这样，
  不需要额外给纹理做动画
- **暗角**只和输出位置有关：挂载时算一张 Float32Array，逐帧直接乘
- **推近** f12–66 `Easing.inOut(cubic)`：focus (0.5, 0.5) → 短语中心，zoom 1.3 → 2.35；
  之后到片尾 zoom 再 linear +0.12（呼吸，不让画面定格）
- **荧光笔** f70–88 `Easing.out(cubic)`：矩形宽 × mask 自左向右，multiply 混合
  `#ffd400` @0.85——浅底变黄、深色字保持深色
- 源图先 `drawImage` 降采样到 2400 宽再取 ImageData：起手 zoom 1.3 下约 1:1 采样
- 全部在 Canvas 2D 里算，canvas 在 `useLayoutEffect` 里逐帧同步重绘；截图解码期间
  `delayRender` 挂起

## 参数表
| 参数 | 典型值 | 调节手感 |
|------|--------|----------|
| 畸变强度 strength | 1.25 | <0.8 读作"轻微广角"，屏摄感消失；>1.8 在起手 zoom 下黑边吃掉 1/3 画面 |
| 起手 zoom | 1.3 | 起手必须看得到弧形黑边，观众第一眼才知道"这是拍的屏幕"；>1.8 起手就没有边框线索 |
| 终点 zoom | 2.35 | 目标短语约占画面宽 1/3；再大扫描线被放到十几像素一条，读作条纹布 |
| 推近 | 54f，inOut cubic | <36f 像变焦抽帧；>72f 前半段观众已经读完页面，失去"被带过去"的感觉 |
| 落定微推 | +0.12 zoom，linear 到片尾 | 完全静止 = 截图定格，手持拍摄感没了；>0.25 读作还在推，荧光笔没有落点 |
| 摩尔纹强度 | 0.2（浅色页面） | 浅色页面上 0.28 已经明显压暗、文字对比下降；深色页面可到 0.3 |
| 扫描线频率 / 屏幕线比 | 900 / 1.045 | 比值越接近 1 拍频条纹越宽越慢；>1.1 变成细碎噪点 |
| 暗角 | amount .85 / radius .72 / soft .45 | amount <0.6 四角太亮，弧形边框不明显 |
| 荧光笔 | 18f，multiply #ffd400 @0.85 | normal 混合会盖住文字；深色页面改 screen 混合 |

## 已知坑
- **荧光笔坐标必须实测**。目测估的坐标在截图像素里差 50px，推近到 2.35× 后就是半个
  单词——本卡首版就把 "better" 的前三个字母漏在了外面。做法：ffmpeg 裁出目标行、
  画 25px 网格放大 3 倍读坐标
- 源图不要直接采 4K 原图：2× 以上缩小采样时小字自己会混叠出一层假摩尔纹，和算出来
  的摩尔纹叠在一起变脏。先用浏览器 `drawImage` 降采样
- 取景坐标的单位高度是"截图宽 ÷ 16:9"，不是截图高。截图不是 16:9 时 y 换算用错，
  整个画面会纵向拉伸
- 不用 WebGL 是刻意的：无头渲染不依赖 GPU、逐帧确定。代价是每帧 200 万像素的 JS 循环，
  Studio 预览可能掉帧。改写成 fragment shader 预览会流畅，但要逐个渲染环境验证
  WebGL 可用（无 GPU 的 CI 上通常要 `--gl=angle`/`swangle` 之类的参数）
- 素材必须是**真实截图**（Q1），而且要对得起特写：推近后画面里只剩一两行字，那行字
  就是整个镜头的信息
- 目标短语贴近页面顶/底边时，推近后越界区域变成大片黑边，读作"拍歪了"。目标尽量
  选页面中部，或给截图上下补边
- 屏摄是反差质感，一支片最多用一次；紧挨着干净 UI 镜头效果最好，连用两镜就变成滤镜
